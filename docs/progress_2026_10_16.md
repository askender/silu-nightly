## Inheritance decision review (after import landed, 9a0827b)

Cross-file import changes the picture: the .si port is no longer
forced into one file (llvmlite.si imports separately). Three
options for the TypedCodegen(SiluToLLVMConverter) inheritance:

1. Flatten at port time (recommended): a small generator script
   merges the two classes' methods into one .si class
   mechanically. Re-merge = re-run the script, so the "drift"
   cost of flattening disappears; Python sources keep the
   inheritance and the dynamic backend stays untouched.
2. Add class inheritance to Silu: rejected - Rust has none (fragile
   base problem, implementation inheritance couples reuse with
   polymorphism), and it would have to land on six surfaces for one
   use case.
3. Rust-style composition in Python now: the correct end state, but
   it is exactly the deferred P1 refactor (template-method
   inversion of convert(), 82 shared attrs explicit) - largest
   effort, highest risk, and orthogonal to getting the port done.

Plan: option 1 now; option 3 remains the P1 refactor. When it
lands, the flatten script degenerates to a no-op.

## Native dispatch chain: the class-identity family fixed (2026-10-18)

The `no field 'triple'` module-init panic and the segfault cascade
behind it were all one family: instance class identity did not
survive the compile-time lifetime of a value. The id()-keyed
`_inst_class` dict only knew construction sites and field reads, so
loads, call results and parameters boxed with cid=-1 and the
dispatch chains fell through. Structural fix: the kind string now
carries the class (`"instance:Token"`, mirroring `"func:"+name`),
and `_box` stamps the cid from the kind. The id() dict is gone.

Fixes landed along the chain (each found by the next crash):

- kind carries class: helpers `_inst_kind/_is_inst/_kind_cls/
  _kind_llvm_key`; producers (construct, field read, static call and
  method-call results, funcref calls, params, loop targets, name
  bindings) emit classed kinds; `_declare_var` upgrades from
  `_var_class`; coerce/unbox/is-compare/if_expr/declare sites
  normalize
- `_collect_ctor_returns` sees through `x = Ctor(...); return x`
  (per-function ctor-bind map) - `scope_new()`-style factories then
  class their call results
- `_unbox(obj, INSTANCE)` unwraps tag-6 boxes via
  `pyobj_unwrap_instance` instead of blindly bitcasting (dynamic-ABI
  factories return boxes into instance-typed fields)
- `_emit_dyn_method_call` boxes results BEFORE the merge branch
  (instructions after a terminator produced invalid IR) and no
  longer double-boxes PObj* returns (only raw i8* returns get the
  class-stamped wrap)
- `_emit_dyn_attr_read` stamps instance-field boxes with the
  declared field class (`_fc`), and its no-match path panics loudly
  (with the attr) instead of returning a null box
- dynamic-ABI method bodies class their raw params from
  `_var_class` (method self arrived as a plain INSTANCE slot)
- slices on dynamic containers: `pyobj_list_slice` +
  tag-dispatching `pyobj_slice_any` (the OBJ subscript path passed
  slice nodes through as null keys)
- `str_join_boxed` rewritten as a real two-pass pyobj join (the old
  one bitcast a pylist as a raw str list and copied from past the
  buffer end)
- `pyobj_instance_cid` is tag-guarded (non-instance boxes answer -1
  via a `silu_no_cid` cell; isinstance on a non-instance used to
  dereference garbage)
- dead `silu_dbg_i64` helper removed from every generated module

Mini repro `selfhost/t_gep.si` (imports llvmlite.si, builds one gep)
runs native == interpreter. The full native converter now clears

## 经验沉淀：本项目调试方法论（2026-10-19，compact 前存档）

### 1. 自举暴露的 bug 分类学

自举（用 Silu 编译的转换器再编译 Silu 程序）暴露的缺陷分三类，
判定标准很明确：

- **Python 对象模型掩盖的设计缺陷**：如 `id()` 当编译期身份、
  方法名分派优先级。Python 下从不显形，因为 Python 自己的分派
  不依赖我们生成的 cid 链。修法是把它变成显式类型信息
  （kind 字符串携带类名），不是打补丁。
- **Silu/Python 语义差**：`None.text` 在 Silu 经 shim 得 ""、
  在 Python 抛 AttributeError。这类路径 Python 下不可达，只有
  原生能走到（PointerType(None) 缓存键冲突）。修 twin 时两份
  拷贝必须同步改（twin 字节锁）。
- **新代码真 bug**：如终结符后发指令、PObj* 结果二次装箱。
  特征是 IR 审计能直接看出结构错误。

### 2. 调试工具箱（按可靠性排序）

1. **raise 式诊断（最可靠）**：`raise RuntimeError("DBG ..." + x)`
   走 print+exit 路径，exit 会 flush stdio。**print 到管道不行**——
   全缓冲，SIGSEGV 吃掉缓冲区，什么都看不到。pty（script -q）
   也不行——EOF 语义变化，read_stdin 直接返回空。
2. **__silu_line 全局变量**：编译产物每语句前写行号，崩溃后
   lldb 里 `x/1gx <地址>` 直接读出最后执行的 .si 行。**陷阱**：
   import 拼接保留各文件原始行号——行号 ≤1024 是 llvmlite.si
   的行，不是 flat 文件的行（本轮被坑两次）。地址用
   `nm binary | grep silu_line` 查。
3. **断点命令日志**：`b <fn>` + `breakpoint command add 1` +
   `expr -- (void*)$x0` + `continue` + DONE，比一次性 lldb 表达式
   链可靠（后者常解错地址/偏移，本轮 `cell+48` vs `inst+48`
   误读一次导致整段推理作废）。
4. **探针递增法**：selfhost/t_gep.si 为基座，每次加一两行
   复刻崩溃链，跑 native vs interpret 对拍。**必须先**
   `cp selfhost/llvmlite.si /tmp/llvmlite.si`——/tmp 副本不会
   自动更新（本轮全部 /tmp 探针结果因旧副本作废过一次）。
5. **诊断信息设计**：报"值的来源"比报"值的现状"有用——
   `ptr.opname`（哪条指令产的）、`ptr.type.text`（什么类型）、
   `len(indices)`（哪个调用形态）。gvar/Argument 没有 opname，
   会变成新的 AttributeError。

### 3. 已固化的门禁流程

每个里程碑：改代码 → 门禁（test_llvmlite_text 27 项覆盖四层：
文本层 vs 真 llvmlite 字节一致 / flatten --si 过 check /

### 所有坑的根源总结（用户要求）

11 个跨平面缺陷，归为四个结构性根源（全部是"Python 平面天然
正确、原生平面显形"）：

**根源 A：未处理语法节点静默降级为 null**（贡献最多）
- multi_assign（#9）：链式赋值 `a = b = None` 的存储全部静默跳过
  → 未初始化栈槽读垃圾 → 追了几场的"堆损坏""funcref 盒泄进
  is_null/const_node 槽""cid 之谜"全是它的随机表现。ASan 全绿
  因为不是越界——是合法槽位的合法读，只是没人写过。
- chained_compare（#12）：链式比较恒假（本段）。
- 列表推导式（#5）：原生平面把推导式降级为 null 赋值。
教训：**双平面后端的"unknown op → null"默认路径是系统性盲区**
——任何 IR 生成器会发、而后端不认识的节点都静默产生错误语义。
正确姿势是 unknown op 响亮 panic（当时为了兼容旧代码没改）。

**根源 B：双平面 API 语义分裂**
- str(x.type)（#11）：真 llvmlite str() 得 "i8*"，twin Type 的
  str() 是 repr → self-first 判定恒假 → 分发元数全体偏移。
- %格式化（#4）、Silu 无默认参数（运行时才炸）。
教训：**凡在转换器源里调用 Python 内建（str/len/列表推导/
关键字参数），必须逐一确认 twin 语义一致**；flatten 的元数补全
（NON_BUILDER_RECV 白名单）会把同名方法调用改写——新代码用
`.add(` 必须核白名单。

**根源 C：名字键副作用表跨作用域泄漏**（#8）
- var_class/var_kinds(instance:X)/_list_elem_class 以变量名为键，
  模块级条目经函数作用域拷贝被继承——函数内重绑的同名短名
  （c/b/fn，twin 满篇）拿错类。
- nested_hoist 的 funcref 改写同样作用域盲（#10）：提升函数名
  与局部同名时，局部的每次使用都被改成 funcref 节点。
教训：**任何"按名字查表"的编译期状态都要显式建模作用域**——
Python 的字典语义天然无作用域，而变量名会在嵌套作用域里复用。

**根源 D：真运行时数据结构的边角缺口**
- list_insert 不写 capacity（堆越界写，布局敏感、ASan 掩盖）、
  set.update 路由进 dict 写坏结构、dict.keys/values 路由错、
  list×int 无运行时、jr_number 的 i64 溢出、超大字面量序列化。
教训：这些只在"转换器转换自己"的规模与形态下被踩到——
**自应用是最强的模糊测试**，16 个小程序门禁永远测不到。

**方法论沉淀**（按见效排序）：.ll 手术 printf（tag/表索引/行号
三件套，一轮定身份）> 双平面状态转储对比（推断 sigs/类布局/
