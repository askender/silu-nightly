# Progress and plan (pre-compact checkpoint, 2026-10-16)

## Just landed

**Nested def + lambda** (commit 2d36c2e) with Rust nested-item
semantics across all six surfaces, and **f-string via ir2c** (commit
1fc08ff). Full suite: 955 passed, 2 skipped.

The design, recap: both front ends (Python `ir_generator.py` and the
self-hosted `silu_fe.si`) run an identical hoist pass. Nested defs and
lambdas become module-level functions with mangled path names; closure
capture is a compile error; `self` is the one exception — a hoisted
function touching self gets a leading self parameter, call sites thread
it by fixpoint. Lambdas desugar to a hoisted def plus a `funcref`
node. See `docs/feature_coverage.md` for the six-surface checklist.

Bug fixes along the way (all in the same two commits): ir2c decl dedup
for sibling loops, obj-annotated ann_assign boxing (was a SEGV),
empty-list PObj typing, null-safe pyobj_eq/isinstance in typed LLVM.

## Current state of the pipeline

- Front ends: Python `ir_generator.py` and `selfhost/silu_fe.si`, IR
  byte-identical on every test
- Back ends: AST interpreter, IR interpreter, typed LLVM
  (`silu/typed_codegen.py`, llvmlite text layer), and the pure-Silu
  `selfhost/ir2c.si` -> C -> clang chain
- Self-hosting: the toolchain compiles itself (M5 closed-loop intact)
- Benchmarks: 13/14 byte-identical vs CPython, geomean 0.97x
  (`jsonparse.si` remains a known gap — heterogeneous dynamic program)

## Known gaps / not done

- ir2c's funcref only resolves when the lambda local is called by
  direct name in the same function; passing a funcref around as a
  value is not supported on the C backend (typed backend is the same).
- The capture-rejection message text differs slightly between the two
  front ends (same meaning).
