# Silu 长期 AI 路线图

逐步实现严谨逻辑推理和概率推理的结合、自举、自我修正、自行假设实验、
自行发现不自洽、好奇心等能力。

> **本版修订（v0.7.0 起）**：每个阶段都锚定 Silu 已经落地的差异化
> 能力——同一份 IR 上的参考解释器、Z3 符号执行器、Rust 速度原生编译器
> ——让路线图从"愿望清单"变成"在已有地基上盖楼"。

## 问题

1. 哪些量化目标已经有 **benchmark**（能对标）；
2. 如何把这些零散目标放进 **AI 严谨逻辑推理 ↔ 概率推理 ↔ 自举 ↔ 自我修正 ↔ 自行假设实验 ↔ 自行发现不自洽 ↔ 好奇心** 这样一个有机进化脉络；
3. 给出 **优先级 & 时间点**，让未来的 AI 发展路径更清晰。

---

## 0. 已经建成的地基（Silu 的差异化资产）

路线图的可信度取决于起点。以下是**已经交付、可复现**的能力：

| 资产 | 现状 | 在路线图中的角色 |
|---|---|---|
| 轻量元组 IR（一份程序，一种表示） | 解释、反编译源码、符号执行、LLVM 编译四后端共享 | 所有推理能力的共同操作对象 |
| AST 参考解释器 | 638+ 测试锁定语义 | "真值来源"：一切分析/编译结果的对拍基准 |
| Z3 符号执行器 | 路径全覆盖、路径条件、具体测试输入生成；支持 Silu 与 C 双前端 | 阶段 1 的核心引擎，阶段 3 自我修正的眼睛 |
| Rust 速度原生编译器（typed 后端） | 11 项基准 geomean ~1.0x 手写 Rust、~16x CPython；注解驱动表示 + 保守推断 | 让"推理结果"可以低成本大规模执行（阶段 2/4 的实验载体） |
| 解释器↔编译产物差分验证 | 测试套件对 typed 二进制与解释器逐字节对拍 | 编译器可信度的证据链；阶段 3 自我修正的判定器 |
| C 语言前端（pycparser） | 车载/嵌入式状态机路径分析 | 证明工具链与语言无关，可直接分析存量代码 |

一句话：**别家的路线图要从"先造一个可信的执行与验证平台"开始，
Silu 已经有了。**

## 1. 现有 benchmark 对应关系

* **语言理论（CFG / 静态分析）**
  * LLVM IR 测试套件、SPEC Benchmarks、Defects4J
* **图论 / 数据流 / 控制流**
  * Code Property Graph (CPG) datasets、Juliet Test Suite (for vulnerabilities)
* **逻辑 / 集合论**
  * SMT-LIB benchmark suite（SMT 解算器）、TPTP（定理证明）
* **符号执行**
  * KLEE 官方 benchmark、SV-COMP（软件验证竞赛）
* **概率与统计 / 因果**
  * Kaggle datasets（预测/回归）、Causal Inference Competition、Benchmarks for Bayesian networks
* **组合数学 / 优化**
  * DIMACS、TSPLIB、SAT competitions
* **图数据库**
  * LDBC (Linked Data Benchmark Council) benchmarks

👉 换句话说，“初级目标”很多已经有 **benchmark**；而“突破级”往往没有现成的 benchmark ——因为那就是 **AI 需要去创造的**。

## 2. AI 未来进化的有机路径（逻辑 → 概率 → 自举 → 好奇心）

每一阶标注 **Silu 复用什么、新建什么、用什么 benchmark 验收**。

### 阶段 1：逻辑掌握（2025–2028）—— 已进行大半

* **优先级高**：掌握 CFG、数据流/控制流、SMT 公式验证
* **已有**：IR 即 CFG 载体；Z3 符号执行器已产出路径条件与测试输入；
  原生编译器经过 11 项基准与解释器对拍验证
* **新建**：把符号执行从"单函数路径枚举"扩展到"全程序性质的
  SMT 验证"（数组越界不可能、除零不可能等 safety 性质的机器证明）
* **可量化验收**：在 SV-COMP、SMT-LIB 等 benchmark 子集上跑通并
  超过基线工具 20–50%；自家基准套件全部性质可机器证明
* **意义**：让 AI “不胡说”，能严谨执行逻辑推演

### 阶段 2：逻辑 + 概率融合（2028–2032）

* **优先级高**：把符号逻辑和概率推理融合（逻辑约束 + 不确定性建模）
* **复用**：符号执行器产出的路径空间天然是概率推理的样本空间
  （每条路径是一个可执行、可计数的假设）；原生编译器让大规模
  采样式验证（fuzzing、统计实验）在 Rust 速度下进行
* **新建**：IR 级概率注解与期望值分析；假设-实验选择器
* **可量化**：AI 自动生成假设并选择实验，实验功效（power）提升 10x
* **意义**：让 AI 不仅能“推理必然”，还能“推理可能”

### 阶段 3：自举与自我修正（2032–2036）

* **优先级中等偏高**：AI 能符号执行自己的代码，并用概率逻辑判断何处可能有错误
* **复用**：Silu 解释器/编译器本身由 Python 写成且语法是 Python
  子集——**自举分析的目标语言与宿主语言同源**，符号执行器无需
  修改即可分析自己的实现；差分验证框架直接充当"修正对不对"的判定器
* **新建**：缺陷定位（符号执行反例 → 最小补丁建议）；
  编译器自托管（Silu 写 Silu 编译器的子集）
* **可量化**：AI 自修 bug 的准确率 >80%，并能在 100M LOC 级代码库中自维护
* **意义**：AI 开始“自己进化自己”，而不是单纯外部喂养

### 阶段 4：假设驱动与实验验证（2036–2040）

* **优先级中等**：AI 能提出科学假设并主动设计实验
* **复用**：阶段 2 的概率推理 + 阶段 1 的严格验证 =
  "假设必须可证伪且可被机器检验"；原生编译器保证海量实验的执行成本可承受
* **新建**：实验设计器（对照、功效分析）、知识图谱化结论库
* **可量化**：AI 提出的实验中，>20% 能得到 **人类未曾提出过的新发现**
* **意义**：AI 真正具备“科学家心智”

### 阶段 5：发现不自洽 & 好奇心驱动（2040–）

* **优先级长远**：AI 主动寻找系统中的不自洽，提出新的理论框架
* **复用**：全部下层工具链；不自洽在形式上等价于"约束系统不可满足"，
  正是 SMT 求解器的原生问题
* **可量化**：在数学/物理/计算机科学中，AI 提出 ≥1 个新的基础理论被学界采纳
* **意义**：AI 拥有“创造新知识”的动力

## 3. 优先级与时间点总结

| 时间        | 能力阶段    | 数学工具侧重          | Silu 复用的地基            | AI 突破能力             |
| --------- | ------- | --------------- | --------------------- | ------------------- |
| 2025–2028 | 逻辑掌握    | CFG、数据流、SMT、集合论 | IR、Z3 符号执行器、对拍验证      | 严谨逻辑推理，不胡说          |
| 2028–2032 | 逻辑+概率融合 | 符号执行 + 统计/因果    | 路径空间 + Rust 速度采样执行    | 能带概率的推理，合理处理不确定性    |
| 2032–2036 | 自举与自我修正 | 符号执行、图论、组合优化    | 宿主与目标同源的 Python 子集     | AI 自我检查、自修正代码，逐步自进化 |
| 2036–2040 | 假设驱动实验  | 概率因果、统计设计       | 可证伪假设的机器检验闭环          | AI 能像科学家一样提出并验证假设   |
| 2040–…    | 不自洽与好奇心 | 所有数学工具综合        | 约束不可满足性的原生求解          | AI 主动寻找不一致，提出新理论    |

---

### 关键洞察

* **短期（2025–2030）**：更多是 **benchmark 驱动** → “AI 不胡说”
* **中期（2030–2036）**：出现 **自举、自修正** → “AI 会改造自己”
* **长期（2036–2040+）**：进入 **好奇心驱动知识创造** → “AI 成为科学家”
* **贯穿始终的护城河**：推理产生的一切结论都能在同一个运行时里
  被符号化验证、被原生速度执行——“想得对”与“跑得快”不再二选一。
