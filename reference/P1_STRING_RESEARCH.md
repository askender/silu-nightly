# P1 前置研究：字符串 copy 规则的开销量化（2026-11-08）

> 目的：为 P1（统一字符串表示）的语言设计决策提供数据。本文只测量、
> 不实施。环境：M 系列 mac，clang -O2，Silu 1.17.0（tag v1.17.0 后，
> 含 P5）。复现：本文每个基准的完整源码在文中，`python -m silu build`
> 即可重跑。

## 1. 静态面：字符串操作调用点分布

各语料 .ll 输出中的 rawstr_* 调用点（文本层平面）：

| 语料 | rawstr_copy | rawstr_append | rawstr_concat | rawstr_free |
|---|---|---|---|---|
| silu_fe.si（编译器自身） | **180** | 22 | 36 | 201 |
| jsonparse.si | 10 | 1 | 1 | 21 |
| ir_interp.si | 28 | 1 | 7 | 86 |

**读数**：编译器自身的 copy 点是 append 的 **8 倍**——字符串处理
的成本大头在 copy 规则（参数/返回/字段边界），不在原地 append。
原地 append 全语料仅 22+1+1 处，是**窄窗优化**而非主流形态。

## 2. 动态面：3M 次单字符拼接微基准

四种写法，同一语义（把 "x" 拼接 3,000,000 次）：

| 形态 | 写法 | 耗时 | 相对纯循环 |
|---|---|---|---|
| 纯循环基线 | `acc += 1`（无字符串） | 0.03s | 1× |
| **局部变量原地 append** | `a = a + "x"`（循环内，局部） | **0.03s** | **1×** |
| 函数边界返回 | `b = addch(b, "x")`，addch 内 `return s + c` | **33.5s** | **~1100×** |
| **实例字段赋值** | `b.s = b.s + c`（addch(b, c) 内） | **34.9s** | **~1160×** |

补充发现（尝试写"跨函数共享可增长字符串"时的语言空缺）：
- `global` 语句：IR 生成不支持（"Unsupported syntax: Global"）；
- 构造器内 `self.s: str = ""`：不支持（仅简单变量注解赋值）——
  类字段形态须用类体 `s: str = ""` 声明。

## 3. 结论

1. **现状的"原地 append"是一扇极窄的窗**：仅当目标是**局部变量**且
   严格 `x = x + t` 形态时 O(1) 摊还。目标换成实例字段、或拼接发生在
   函数边界（哪怕语义完全相同），立即退化为 O(n²)——**1000 倍级罚款**。
   silu_fe 自身的热循环（`lit = lit + ch`，parse_fstring L828 等）
   恰好全在窗内，这是**运气好**而不是设计保证。
2. **copy 规则是真实且广泛的开销**（180 调用点/编译器自身），但它
   分布在非热路径（短字符串参数/字段传递，单次 O(n) 且 n 小），
   现状可接受；真正的问题不是 copy 本身，而是**O(1) 拼接契约的缺失**。
3. **1b strbuf 的价值据此上升**：`buf.push(c)` 把 O(1) 摊还从
   "编译器对局部变量窄窗的隐式识别"变成**显式、上下文无关的语言
   契约**——字段里、跨函数、任何地方。研究期间发现的两处语言空缺
   （global 语句无 IR、构造器注解赋值）也说明"共享可变缓冲"目前
   在 silu 里**写不出来**，strbuf 填的正是这个洞。
4. **1a（refcount 不可变 str）不解决本问题**：refcount 只消除边界
   copy（180 个调用点的税），`s = s + c` 仍需 concat 新建（O(n)/次）
   ——除非另做隐式 buffer 优化，那等于把 strbuf 的实现复杂度藏回
   编译器，还叠加 refcount 成本。

### 对 P1 决策的数据支撑

| 方案 | 窄窗 O(1) 保留 | 任意上下文 O(1) | 边界 copy 税 | 新语言面 |
|---|---|---|---|---|
| 维持现状 | ✓（局部窄窗） | ✗（字段/跨函数 1000×） | 保留 | 无 |
| 1a refcount | 需另做隐式优化 | 同左 | 消除 | refcount 语义 |
| **1b strbuf** | ✓（显式契约） | ✓ | 保留（str 域不变） | +1 类型 +~4 方法 |
| 1b + 局部窄窗优化保留 | ✓ | ✓ | 保留 | 同 1b |

数据指向：**1b（显式 strbuf）+ 保留现有局部 append 窄窗优化**是
唯一同时覆盖"热循环 O(1) 无处不在"与"零隐藏成本"的选项；维持现状
的代价是把性能押在窄窗运气上（换一种写法即 1000×）。

## 4. 基准源码（完整可复现）

形态 A/B/C 见 git 历史（本文件提交信息附三份 .si 全文）；类字段形态：

```python
class B:
    s: str = ""

def addch(b: B, c: str) -> object:
    b.s = b.s + c
    return None

def main() -> int:
    n: int = 3000000
    b: B = B()
    i: int = 0
    while i < n:
        addch(b, "x")
        i += 1
    print(len(b.s))
    return 0
```
